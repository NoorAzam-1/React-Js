Introduction to React

React is a declarative, component-based JavaScript library created by Meta (Facebook) for building user interfaces. Instead of manipulating the DOM directly (imperative), you describe what the UI should look like for a given state, and React handles the DOM updates.

Declarative vs Imperative

In traditional JavaScript (imperative approach), you manually tell the browser how to update the UI step by step — find the element, change its text, add a class, etc. In React (declarative approach), you simply describe what the UI should look like for a given state, and React handles all the DOM updates automatically behind the scenes. 

// Imperative (Old way) — You do everything manually
const el = document.getElementById("title");
el.textContent = "Hello World";
el.classList.add("active");

// Declarative (React way) — Just describe what you want
return <h1 className="active">Hello World</h1>;
What is the Virtual DOM?

The Virtual DOM is React's secret weapon for performance. It is a lightweight copy of the real DOM kept in memory. Here is how it works step by step:

  • State Change: When state changes (e.g., a button click updates a counter), React creates a new Virtual DOM tree representing the updated UI.
  • Diffing: React compares the new Virtual DOM tree with the previous one using the Diffing Algorithm. It finds exactly which nodes changed.
  • Reconciliation: React calculates the minimal number of changes needed to update the real DOM.
  • Batch Update: React applies only the necessary changes to the real DOM in one batch, not one-by-one.

Example: If you change a list item in a list of 1000 items, React will NOT rebuild the entire list. It will only update that one specific item in the real DOM — making it blazing fast.

Key Features of React
  • Component-Based: UI is broken into small, reusable pieces called components.
  • Learn Once, Write Anywhere: You can use React for web (React DOM), mobile (React Native), and even desktop (Electron).
  • Unidirectional Data Flow: Data flows from parent to child (via props), making the app predictable and easy to debug.
  • Rich Ecosystem: Huge community, thousands of libraries (React Router, Redux, Material UI, etc.).
  • JSX Syntax: Write HTML-like code directly inside JavaScript for a cleaner developer experience.

JSX (JavaScript XML)

JSX stands for JavaScript XML. It is a syntax extension that allows you to write HTML-like code directly inside JavaScript files. JSX is not valid JavaScript by itself — it gets compiled by Vite/Babel into regular JavaScript function calls.

Without JSX vs With JSX
// ❌ WITHOUT JSX (Verbose and hard to read)
const element = React.createElement('div', { className: 'container' },
  React.createElement('h1', null, 'Hello, World!'),
  React.createElement('p', null, 'This is without JSX.')
);

// ✅ WITH JSX (Clean and readable)
const element = (
  <div className="container">
    <h1>Hello, World!</h1>
    <p>This is with JSX.</p>
  </div>
);
Rule 1: Return a Single Parent Element

JSX expressions must have one parent element. If you have multiple elements at the same level, wrap them in a <div> or use a Fragment (<>...</>). 

// ✅ Correct — Single parent div
return (
  <div>
    <h1>Hello</h1>
    <p>World</p>
  </div>
);

// ✅ Correct — Using Fragment (no extra div in DOM)
return (
  <>
    <h1>Hello</h1>
    <p>World</p>
  </>
);

// ❌ Wrong — Two elements without a parent
return (
  <h1>Hello</h1>
  <p>World</p>
);
Rule 2: Use className Instead of class

In HTML, you use the class attribute. But in JSX, class is a reserved keyword in JavaScript, so React uses className instead. Same for htmlFor (instead of for). 

// ❌ Wrong in JSX
<div class="container">...</div>

// ✅ Correct in JSX
<div className="container">...</div>

// Same for htmlFor (instead of for)
<label htmlFor="email">Email:</label>
Rule 3: JavaScript Expressions in Curly Braces {}

Any valid JavaScript expression can be embedded inside JSX using curly braces {}. This includes variables, function calls, ternary operators, array methods, and more. 

const name = "Ahmad";
const isLoggedIn = true;
const items = ["React", "Vue", "Angular"];

const element = (
  <div className="container">
    {/* Variable */}
    <h1>Hello, {name}!</h1>

    {/* Ternary Operator */}
    <p>{isLoggedIn ? "Welcome back!" : "Please login"}</p>

    {/* Function Call */}
    <p>Current time: {new Date().toLocaleTimeString()}</p>

    {/* Array Map */}
    <ul>
      {items.map((item, index) => (
        <li key={index}>{item}</li>
      ))}
    </ul>
  </div>
);
Rule 4: Inline Styles Use Objects

In HTML, you write styles as strings. In JSX, styles are passed as JavaScript objects with camelCase property names. 

// ❌ Wrong — String format like HTML
<div style="color: red; font-size: 16px;">...</div>

// ✅ Correct — Object format with camelCase
<div style={{ color: 'red', fontSize: '16px' }}>...</div>
Rule 5: Self-Closing Tags Are Mandatory

In HTML, some tags like <img>, <input>, <br> can be left open. In JSX, every tag must be explicitly closed. 

// ❌ Wrong in JSX
<img src="photo.jpg">
<input type="text">
<br>

// ✅ Correct in JSX
<img src="photo.jpg" alt="Photo" />
<input type="text" />
<br />
Rule 6: Comments in JSX

Single-line comments use {/* comment */} syntax inside JSX. 

<div>
  {/* This is a JSX comment */}
  <h1>Hello World</h1>
</div>

Components in React

Components are the building blocks of any React application. A component is a reusable piece of UI that can manage its own logic and rendering. Every React app is made up of multiple components working together.

Functional Component (Modern Standard) ✅

A functional component is simply a JavaScript function that returns JSX. It receives data via props (properties) as an argument. 

// Simple Functional Component
function Greeting({ name }) {
  return <h1>Hello, {name}!</h1>;
}

// Arrow Function Version
const Greeting = ({ name }) => {
  return <h1>Hello, {name}!</h1>;
};

// Even shorter (implicit return)
const Greeting = ({ name }) => <h1>Hello, {name}!</h1>;

How to use (call) a component: 

// In parent component or App.jsx
<Greeting name="Ahmad" />
<Greeting name="Sara" />
<Greeting name="Ali" />

// Output:
// Hello, Ahmad!
// Hello, Sara!
// Hello, Ali!

Key characteristics of Functional Components:

  • Simple JavaScript function — no special syntax needed
  • Props are received as the first argument (destructured directly)
  • Returns JSX which describes the UI
  • Hooks (useState, useEffect, etc.) can be used inside them
  • Component name must start with a capital letter (e.g., Greeting, not greeting)
  • The file name should match the component name (e.g., Greeting.jsx)
Functional vs Class — Comparison

// Syntax         Simple function             ES6 class + render()
// State          useState hook               this.state + this.setState()
// Lifecycle      useEffect hook              componentDidMount, etc.
// Props          { name } (destructured)     this.props.name
// Performance    Slightly faster             Slightly slower
// Hooks          ✅ Yes                      ❌ No
// Recommended    ✅ Yes                      ⚠️ Legacy only

Props and State

Props and State are the two main ways data flows in React. Understanding both is essential for building dynamic applications.

What are Props?

Props (short for properties) are read-only arguments passed from a parent component to a child component. They are like function parameters — you pass data in, and the child uses it. Props flow in one direction only: parent → child. 

// Parent passes props to child
<UserCard name="Ahmad" age={25} isOnline={true} />

// Child receives and uses props
function UserCard({ name, age, isOnline }) {
  return (
    <div>
      <h2>{name}</h2>
      <p>Age: {age}</p>
      <p>Status: {isOnline ? "Online 🟢" : "Offline 🔴"}</p>
    </div>
  );
}
Props Rules
  • Props are read-only — a child component cannot modify the props it receives.
  • You can pass any data type: strings, numbers, booleans, arrays, objects, functions, even other components.
  • You can set default values for props using destructuring.
  • props.children is a special prop that holds whatever you put between a component's opening and closing tags. 
// Default Props
function Button({ text = "Click me", color = "blue" }) {
  return <button style={{ backgroundColor: color }}>{text}</button>;
}

// props.children — Wrapping content
function Card({ children }) {
  return <div className="card">{children}</div>;
}

// Usage
<Card>
  <h2>Title</h2>
  <p>Some content inside the card</p>
</Card>
What is State?

State is internal data owned and managed by a component. When state changes, React re-renders the component to reflect the new data on screen. Unlike props, state is mutable — you can change it using the setter function. 

function Counter() {
  // useState returns [currentValue, setterFunction]
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Clicked {count} times</p>
      {/* Never modify state directly: count++ ❌ */}
      {/* Always use setter: setCount(count + 1) ✅ */}
      <button onClick={() => setCount(count + 1)}>
        Click me
      </button>
    </div>
  );
}
State Rules
  • Do not modify state directly — always use setState() or the setter function.
  • State updates are asynchronous — React batches updates for performance.
  • State triggers re-render — when state changes, the component and all its children re-render.
  • Each component has its own state — state is local to the component.
Props vs State — Comparison
// Feature        Props                        State
// Owner          Parent component             The component itself
// Mutability     Read-only (immutable)        Mutable (via setState)
// Purpose        Pass data down               Manage internal data
// Trigger        Passed by parent             setState() triggers re-render
// Initialization Passed as arguments          useState() or this.state = {}
Lifting State Up

Sometimes two sibling components need to share the same data. The solution is to lift the state up to their closest common parent and pass it down via props. 

// Parent owns the shared state
function App() {
  const [temperature, setTemperature] = useState(0);

  return (
    <div>
      <TemperatureInput value={temperature} onChange={setTemperature} />
      <TemperatureDisplay temperature={temperature} />
    </div>
  );
}

// Both children receive state via props
function TemperatureInput({ value, onChange }) {
  return <input type="number" value={value} onChange={(e) => onChange(+e.target.value)} />;
}

function TemperatureDisplay({ temperature }) {
  return <p>Temperature: {temperature}°C</p>;
}
State with Objects and Arrays
// Updating object state — always spread existing state
const [user, setUser] = useState({ name: "Ahmad", age: 25 });

// ✅ Correct — spread existing state, then override
setUser({ ...user, age: 26 });

// ❌ Wrong — replaces entire state, loses 'name'
setUser({ age: 26 });

// Updating array state
const [items, setItems] = useState(["React", "Vue"]);

// Add item

// Remove item
setItems(items.filter(item => item !== "Vue"));

// Update item
setItems(items.map(item => item === "React" ? "React.js" : item));
Multiple State Variables

  const [email, setEmail] = useState("");

    name: "",

React Hooks (Deep Dive)

Hooks are special functions that let you use state and lifecycle features in functional components. They were introduced in React 16.8. Before hooks, these features were only available in class components.

Rules of Hooks
  • Only call hooks at the top level of your component — never inside loops, conditions, or nested functions.
  • Only call hooks from React function components or custom hooks.
  • Hook names always start with use (e.g., useState, useEffect).
1. useState — Local State Management

Manages local component state. Returns an array with the current value and a setter function. The setter triggers a re-render. 

import { useState } from 'react';

function Counter() {
  // useState(initialValue) returns [value, setValue]
  const [count, setCount] = useState(0);
  const [name, setName] = useState("Ahmad");
  const [user, setUser] = useState({ name: "Ahmad", age: 25 });

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={() => setCount(prev => prev + 1)}>+1 (functional)</button>

      <p>Name: {name}</p>
      <button onClick={() => setName("Sara")}>Change Name</button>

      <button onClick={() => setUser({ ...user, age: user.age + 1 })}>
        Increase Age
      </button>
    </div>
  );
}

Why use functional update prev => prev + 1? When new state depends on old state, always use the callback form. This ensures you're working with the latest value, not a stale closure.

2. useEffect — Side Effects & Lifecycle

Handles side effects: API calls, event subscriptions, timers, document title updates, etc. The dependency array controls when it runs. 

import { useEffect } from 'react';

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);

  // Case 1: Runs on EVERY render (no dependency array)
  useEffect(() => {
    console.log("Component rendered");
  });

  // Case 2: Runs ONCE on mount (empty dependency array [])
  useEffect(() => {
    console.log("Component mounted");
    fetchUser();
  }, []);

  // Case 3: Runs when 'userId' changes
  useEffect(() => {
    fetchUser(userId);
  }, [userId]);

  // Case 4: Cleanup function (runs on unmount or before re-run)
  useEffect(() => {
    const socket = connectWebSocket();

    return () => {
      // Cleanup — runs when component unmounts or before effect re-runs
      socket.disconnect();
    };
  }, []);

  const fetchUser = async (id) => {
    const res = await fetch(`/api/users/${id}`);
    const data = await res.json();
    setUser(data);
  };

  if (!user) return <p>Loading...</p>;
  return <h1>{user.name}</h1>;
}

Dependency Array Summary:

// useEffect(() => {})              → Runs after EVERY render
// useEffect(() => {}, [])          → Runs ONCE on mount
// useEffect(() => {}, [a, b])      → Runs when 'a' or 'b' changes
// return () => {}                  → Cleanup function
3. useContext — Global State

Consumes data from a Context Provider without prop drilling. Perfect for theme, auth, language, etc. 

import { createContext, useContext, useState } from 'react';

// 1. Create Context
const ThemeContext = createContext(null);

// 2. Provider Component (wraps app)
function ThemeProvider({ children }) {
  const [theme, setTheme] = useState("light");
  const toggleTheme = () => setTheme(prev => prev === "light" ? "dark" : "light");

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

// 3. Any child component consumes context
function ThemedButton() {
  const { theme, toggleTheme } = useContext(ThemeContext);

  return (
    <button onClick={toggleTheme} className={theme}>
      Current theme: {theme}
    </button>
  );
}
4. useRef — DOM Access & Persistent Values

Creates a mutable reference that persists across renders WITHOUT causing a re-render. Two main uses: accessing DOM elements and storing values that don't trigger re-render. 

import { useRef, useEffect } from 'react';

function SearchInput() {
  const inputRef = useRef(null);
  const renderCount = useRef(0);

  // Access DOM element directly
  const focusInput = () => {
    inputRef.current.focus();
  };

  // Store mutable value (doesn't trigger re-render)
  useEffect(() => {
    renderCount.current += 1;
  });

  return (
    <div>
      <input ref={inputRef} type="text" placeholder="Search..." />
      <button onClick={focusInput}>Focus</button>
      <p>Rendered {renderCount.current} times</p>
    </div>
  );
}
5. useReducer — Complex State Logic

An alternative to useState for complex state logic. Useful when state has multiple sub-values or when next state depends on previous state. Similar to Redux pattern. 

import { useReducer } from 'react';

const reducer = (state, action) => {
  switch (action.type) {
    case 'increment': return { ...state, count: state.count + 1 };
    case 'decrement': return { ...state, count: state.count - 1 };
    case 'reset': return { count: 0 };
    case 'set': return { ...state, count: action.payload };
    default: return state;
  }
};

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });

  return (
    <div>
      <p>Count: {state.count}</p>
      <button onClick={() => dispatch({ type: 'increment' })}>+</button>
      <button onClick={() => dispatch({ type: 'decrement' })}>-</button>
      <button onClick={() => dispatch({ type: 'reset' })}>Reset</button>
      <button onClick={() => dispatch({ type: 'set', payload: 10 })}>Set to 10</button>
    </div>
  );
}
6. useMemo — Cache Expensive Calculations

Caches the result of an expensive calculation so it only recomputes when dependencies change. Prevents unnecessary recalculations on every render. 

import { useMemo } from 'react';

function FilteredList({ items, filter }) {
  // Without useMemo: runs on every render
  // const filtered = items.filter(item => item.includes(filter));

  // With useMemo: only recalculates when items or filter changes
  const filtered = useMemo(() => {
    console.log("Filtering..."); // Only logs when dependencies change
    return items.filter(item => item.includes(filter));
  }, [items, filter]); // Dependencies

  return <ul>{filtered.map(item => <li>{item}</li>)}</ul>;
}
7. useCallback — Cache Function Definitions

Caches a function definition between re-renders. Useful when passing callbacks to child components that use React.memo. 

import { useCallback } from 'react';

function Parent() {
  const [count, setCount] = useState(0);

  // Without useCallback: new function every render → child re-renders
  // const handleClick = () => console.log(id);

  // With useCallback: same function reference between renders
  const handleClick = useCallback(() => {
    console.log("Clicked");
  }, []); // No dependencies = never changes

  return (
    <div>
      <p>{count}</p>
      <MemoizedButton onClick={handleClick} />
    </div>
  );
}
8. useLayoutEffect — Synchronous DOM Measurements

Same as useEffect, but fires synchronously after DOM mutations but before the browser paints. Use when you need to measure DOM elements (scroll position, element size) before the user sees the screen. 

import { useLayoutEffect, useRef, useState } from 'react';

function Tooltip() {
  const ref = useRef(null);
  const [height, setHeight] = useState(0);

  useLayoutEffect(() => {
    // Measure BEFORE browser paints
    const h = ref.current.getBoundingClientRect().height;
    setHeight(h);
  }, []);

  return <div ref={ref}>Tooltip height: {height}px</div>;
}
9. useImperativeHandle — Custom Handle for ref

Customizes the instance value that is exposed to parent components when using ref. Lets you control what the parent can do with the child's ref.

function useLocalStorage(key, initialValue) {

}

Error Boundaries

Error Boundaries are React components that catch JavaScript errors anywhere in their child component tree, log those errors, and display a fallback UI instead of crashing the entire app. They require a Class Component (no hook equivalent yet).

Why Error Boundaries?

Without error boundaries, if one component throws an error, the entire app crashes. Error boundaries let you gracefully handle errors and show a user-friendly message.

Creating an Error Boundary
class ErrorBoundary extends React.Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false, error: null };
  }

  // Static method to update state when error occurs
  static getDerivedStateFromError(error) {
    return { hasError: true, error: error };
  }

  // Log error to error reporting service
  componentDidCatch(error, errorInfo) {
    console.error("Error caught:", error);
    console.error("Component stack:", errorInfo.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return (
        <div className="error-fallback">
          <h2>Something went wrong.</h2>
          <p>{this.state.error?.message}</p>
          <button onClick={() => this.setState({ hasError: false })}>
            Try Again
          </button>
        </div>
      );
    }
    return this.props.children;
  }
}
Using Error Boundary
// Wrap components that might error
function App() {
  return (
    <div>
      <Header />
      <ErrorBoundary>
        <UserProfile /> {/* If this crashes, only this section shows fallback */}
      </ErrorBoundary>
      <Footer />
    </div>
  );
}
What Error Boundaries Catch vs Don't Catch 
// ✅ CATCHES:
// - Rendering errors (in lifecycle methods, constructors, render)
// - Errors in child components

// ❌ DOES NOT CATCH:
// - Event handler errors (use try/catch for those)
// - Async code (setTimeout, promises)
// - Server-side rendering (SSR)
// - Errors in the error boundary itself

        height: window.innerHeight
      });
      window.addEventListener("resize", handleResize);
      return () => window.removeEventListener("resize", handleResize);
    }, []);

    return <WrappedComponent {...props} windowSize={size} />;
  };
};

Portals

Portals let you render a component's UI into a different DOM node outside of the React component tree. Perfect for modals, tooltips, dropdowns, and overlays that need to break out of parent CSS (like overflow: hidden or z-index issues). 

import { createPortal } from 'react-dom';

function Modal({ isOpen, onClose, children }) {
  if (!isOpen) return null;

        <button onClick={onClose}>Close</button>
      </div>

    document.getElementById("portal-root") // Target DOM node
  );

Performance Optimization

React is fast by default, but as your app grows, you need optimization techniques to prevent unnecessary re-renders and reduce bundle size.

React.memo — Prevent Unnecessary Re-renders

Wraps a component so it only re-renders when its props change. Without memo, a component re-renders every time its parent re-renders, even if its props haven't changed. 

// Without memo — re-renders every time parent re-renders
function UserCard({ name }) {
  console.log("UserCard rendered"); // Logs on every parent re-render
  return <div>{name}</div>;
}

// With memo — only re-renders when 'name' prop changes
const UserCard = React.memo(({ name }) => {
  console.log("UserCard rendered"); // Only logs when name changes
  return <div>{name}</div>;
});

// With useMemo for expensive child props
function Parent() {
  const [count, setCount] = useState(0);

  const userData = useMemo(() => ({
    name: "Ahmad",
    expensiveValue: heavyComputation()
  }), []); // Object reference stays stable

  return (
    <div>
      <p>{count}</p>
      <button onClick={() => setCount(count + 1)}>+</button>
      <UserCard {...userData} /> {/* Won't re-render when count changes */}
    </div>
  );
}
Lazy Loading — Code Splitting

Load components only when needed (on-demand). This reduces the initial bundle size and speeds up loading time. 

import { lazy, Suspense } from 'react';

// Lazy load a component — only imported when rendered
const AdminDashboard = lazy(() => import('./pages/AdminDashboard'));
const Settings = lazy(() => import('./pages/Settings'));

function App() {
  return (
    <Suspense fallback={<p>Loading...</p>}>
      <Routes>
        <Route path="/admin" element={<AdminDashboard />} />
        <Route path="/settings" element={<Settings />} />
      </Routes>
    </Suspense>
  );
}
useCallback + useMemo Combo
// Prevent child re-renders by memoizing both the callback and data
function Parent() {
  const [items, setItems] = useState([]);
  const [filter, setFilter] = useState("");

  const handleClick = useCallback(() => {
    setItems(prev => [...prev, "new item"]);
  }, []); // Never changes

  const filteredItems = useMemo(() => {
    return items.filter(item => item.includes(filter));
  }, [items, filter]);

  return <ItemList items={filteredItems} onAdd={handleClick} />;
}
Performance Tips Summary
  • Use React.memo for pure components that receive same props frequently.
  • Use useMemo for expensive calculations.
  • Use useCallback for functions passed to memoized children.
  • Use React.lazy + Suspense for route-based code splitting.
  • Use useDeferredValue and useTransition (React 18) for non-blocking updates.
  • Avoid inline objects/functions in JSX props (they create new references every render).
  • Use React DevTools Profiler to identify what's causing re-renders.

Redux is a predictable state container for JavaScript apps. When your app grows complex and you need state shared across many components (and Context API isn't enough), Redux provides a centralized store with strict rules for state updates.
